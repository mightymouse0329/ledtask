# robomaster-stage-one：RoboMaster C 板基础功能


本工程包含启动提示音、RGB 流水灯、IMU 串口输出、遥控器通信、电机联动、手动输入及箭头复位的软件实现。电机上电默认锁定；遥控器右拨杆先置下档、再切换到其他档位时自动解锁并记录初始基准，尚待实物验证。

**当前操作以 [统一操作与箭头复位](docs/motor_step_eight.md) 为准。** 下文早期阶段的 ENABLE 开关和单电机实验属于历史记录，当前已采用运行时解锁。

工程采用 STM32CubeMX 配置外设，使用 STM32 HAL 和 FreeRTOS，LED 与蜂鸣器任务采用基础 C 语法直接控制 PWM，在 `applications` 中编写应用任务，通过 CMake 构建。

## 2026-10-07：速度 PID

控制结构为位置 P 外环 → 目标速度 → 速度 PID 内环 → 电流指令。两台电机分别保存积分和微分状态。初始参数位于 `applications/control_constants.hpp`：`MOTOR_SPEED_KP=0.15`、`MOTOR_SPEED_KI=0.05`、`MOTOR_SPEED_KD=0`；D 已实现但初始关闭，所以初始实际运行的是 PI。参数未经过实机整定。

按实际控制间隔积分；微分针对实测速度并滤波；积分电流限制 ±0.10 A，总目标电流限制 ±0.20 A。下档失能、故障、进入联动/复位模式、手动释放对应电机时清除 PID 历史，避免旧积分残留。

调参前确认 IMU READY、两电机在线且角度有效、CAN 无持续错误。右拨杆先置下档，再切至中档或上档，确认 unlocked=1 后进行小角度慢转 C 板。没有解锁时更改 PID 不会使电机运动。先确认方向、target/ref/out 和实际角度，再调增益；不要在未知故障或输出已限流时盲目增加增益。手动输入识别也可能改变目标，应同时观察 MANUAL 状态。

## 2026-10-07：GM6020 电流控制

当前程序发送电流控制帧 `0x1FE`，对应 ID 1、2；反馈 ID 仍为 `0x205`、`0x206`。两台电机应已启用电流环。旧文档中的电压模式 `0x1FF` 和电压输出参数不再适用。

速度误差先转换为目标电流，再按 `16384 / 3` 转换为 CAN 原始值。初始增益为 `0.15 A/(rad/s)`，目标电流限制为 `±0.20 A`（原始值限幅 ±1092），属于待实机调整的起始参数，不保证跟随精度。`LINK ... out` 现在表示电流指令原始值，换算目标电流为 `out * 3 / 16384 A`，并非实测电流。

先保持右拨杆下档，确认橙灯常亮消失、两台电机反馈在线且 CAN 无持续错误。供电稳定后，再将右拨杆切至中档或上档自动解锁并进行小角度测试。故障后需将右拨杆先回下档，再切换到其他档位解锁；失能、失联及故障分支继续发送零电流指令，原有速度、温度和角度保护保留。修改模式不能解决插接导致的断电问题。此次修改尚未编译或实机验证。

## 1. 当前功能与预期效果

| 功能 | 当前代码行为 |
| --- | --- |
| 启动提示音 | 每次程序启动，依次播放约 1000、1500、2000 Hz 三个音，每个音持续约 120 ms，之后静音约 60 ms；播放一遍后停止 |
| RGB 流水灯 | 按红 → 绿 → 蓝循环，各颜色通过 `for` 循环渐亮、渐暗；占空比 0% → 50% → 0%，每步约 30 ms，每步变化 1 个百分点，每种颜色约 3.03 s，一轮约 9.09 s（不含调度和故障等待时间） |
| 心跳监测 | 默认任务每约 20 ms 更新一次心跳计数；LED 任务每约 500 ms 比较一次心跳，未变化时暂停渐变、保持 15% 占空比的红色，并每约 20 ms 等待检查恢复 |
| IMU 串口输出 | 通过 USART1 输出 X、Y、Z 三轴加速度与角速度，每次发送后等待约 100 ms；初始化失败时报告错误并重试 |

这里的流水灯是板载 RGB 灯按颜色依次渐亮、渐暗的效果。蜂鸣器在上电、复位或烧录后程序重新运行时播放，不直接检测烧录器是否下载成功。

上述为源码对应的预期行为，实际验收以开发板运行结果为准。最新变更及编译状态见文末“2026-10-05 更新”。新增遥控器、电机功能均尚待实物验证。

## 2. 硬件与外设

- 开发板：RoboMaster 开发板 C 型，STM32F407 系列。
- 指示器件：使用板载 RGB LED 和蜂鸣器，无需另接同类器件。
- 下载器：当前 OpenOCD 配置使用 CMSIS-DAP；使用无线烧录器时，需确认其支持对应接口并按设备说明完成配对、连接和供电。

| 器件 | 引脚 | 定时器通道 |
| --- | --- | --- |
| 蜂鸣器 | PD14 | TIM4_CH3 |
| 蓝色 LED | PH10 | TIM5_CH1 |
| 绿色 LED | PH11 | TIM5_CH2 |
| 红色 LED | PH12 | TIM5_CH3 |

当前系统时钟为 168 MHz，TIM4、TIM5 的定时器输入时钟为 84 MHz。蜂鸣器任务使用预分频值 `83` 将计数频率降为 1 MHz；修改时钟树后也要检查此参数。

下载连接按开发板和下载器说明核对 SWDIO、SWCLK、GND 及所需参考电压/复位信号，接线时断电。不要把电源电压接到信号引脚；下载器供电能力和开发板供电方式应按硬件说明确认。

### 基础 C 版本说明

LED、蜂鸣器和 IMU 应用任务均使用 `.c` 文件。LED 通过 `led_set()` 设置占空比、通过 `check_heartbeat()` 检查默认任务进度；蜂鸣器使用整数数组和下标循环播放音符；IMU 使用普通函数读写寄存器并发送数据。当前应用不依赖 C++ 类或匿名函数，`sp_middleware` 目录保留供后续学习。

## 5. 程序运行逻辑

1. `main()` 初始化 HAL 和系统时钟。
2. 初始化 GPIO、TIM5、TIM4、SPI1、USART1、USART3 和 CAN1，并启动遥控器接收。
3. `MX_FREERTOS_Init()` 创建默认任务、LED 任务、蜂鸣器任务和 IMU 任务。
4. `osKernelStart()` 启动任务调度。
5. 默认任务循环处理遥控器、电机零指令服务并更新心跳；LED 任务显示渐变灯效；蜂鸣器任务播放一遍提示音后进入周期等待；IMU 任务初始化传感器、读取数据并通过串口发送。

任务使用 `osDelay()` 等待时会让出 CPU，其他就绪任务仍可运行，所以蜂鸣器的音符间隔不会要求 LED 任务一起等待。当前 FreeRTOS 节拍配置为 1000 Hz，实际间隔还受到任务调度影响。

### 心跳（heartbeat）的作用与边界

`app_heartbeat()` 每调用一次就增加一次计数，表示被监测的工作执行到了该位置。LED 任务比较前后两次计数，判断默认任务是否仍在推进。

目前被监测的是默认任务中的简单循环。后续加入实际业务时，应在业务完成一次有效工作后更新对应心跳，避免把无关循环的正常运行误认为业务正常。

如果默认任务停止更新、但 LED 任务还能运行，灯会保持红色。如果整个系统卡死、调度停止或 LED 任务无法获得运行机会，灯可能停在任意颜色，因此不能保证所有故障都会显示红色。本功能不替代硬件看门狗，也不会自动复位系统。正常流水灯也短暂显示红色，应观察颜色是否持续变化。

## 10. BMI088 三轴数据串口输出（基础 C）

### 新增文件及运行过程

- `Core/Src/spi.c`、`Core/Inc/spi.h`：SPI1 初始化，2.625 MHz，模式 3（CPOL 高、CPHA 第二沿）。
- `Core/Src/usart.c`、`Core/Inc/usart.h`：USART1 初始化，115200、8N1、无流控。
- `applications/bmi088_simple.c`、`applications/bmi088_simple.h`：寄存器读写、软复位、芯片 ID 与配置检查、数据换算。
- `applications/imu_task.cpp`：创建后初始化 IMU，约每 100 ms 读取并发送一行文本。
- `main.c` 初始化 SPI1 和 USART1；`freertos.c` 在 USER CODE 的 RTOS_THREADS 区域创建 IMU 任务，栈为 1024 个字（4096 字节）。

两个传感器共用 SPI1，但片选不同：PA4 为加速度计片选，PB0 为陀螺仪片选；PB3=SCK、PB4=MISO、PA7=MOSI。板载连线已存在，无需自行接 IMU 引脚。采用轮询，无需配置 DMA 或传感器外部中断。

### 连接电脑

本版本使用 **外壳 UART2 四针接口，芯片内部实际为 USART1**，TX=PA9、RX=PB7。不要误选 USART2；外壳 UART1 对应的是 USART6。

使用 USB 转 TTL 模块时，推荐 3.3 V 逻辑电平，开发板正常独立供电：

| C 板四针接口的引脚编号（以手册 Pin1 标记为准） | 接到转换模块 |
| --- | --- |
| 1：RXD | TXD（只观察输出时可不接） |
| 2：TXD | RXD |
| 3：GND | GND |
| 4：5V | 不接，避免与其他供电反向供电 |

不要依据插头观察方向猜测编号，也不要使用 RS232 电平直接连接。无线烧录器若支持串口透传，可以将其串口接到上述接口；电脑端口和无线链路也应配置为相同波特率，具体按烧录器说明操作。仅连接 SWD 下载线不会自动传输 USART1 数据。

本版本没有配置 USB CDC，直接连接 C 板的 micro USB 不能通过本程序得到虚拟串口数据。

### 串口助手设置与显示

选择转换模块对应的 COM 口：**115200 波特率、8 数据位、1 停止位、无校验、无流控**，使用文本接收而不是十六进制显示。

复位后初始化成功会输出 `BMI088 OK`，随后持续显示类似下面的内容（示例数据，不是实际测量结果）：

```text
BMI088 OK. ACC: m/s^2; GYRO: deg/s; axes: X,Y,Z
ACC X=0.012 Y=-0.025 Z=9.800 | GYRO X=0.061 Y=-0.122 Z=0.000
```

- ACC：三轴加速度，单位 m/s²，包含静止时的重力响应；配置量程 ±6 g。
- GYRO：三轴角速度，单位 °/s；配置量程 ±2000 °/s。
- 按所提供的 C 板方向图：R 字样上方为 X 正方向，向左为 Y 正方向，Z 正方向垂直板面向外；绕 Z 轴旋转对应 yaw 轴。
- 输出沿用 BMI088 原生三轴顺序，没有额外旋转坐标系。上板时应按方向图逐轴倾斜、转动，确认安装方向与读数符号。
- 这些数据不是 roll/pitch/yaw 姿态角，后续电机联动需要另加姿态解算。当前未实现恒温控制或零偏校准，静止时角速度有小偏差是可能的。

### 异常处理和配置维护

初始化失败会每秒输出错误码并重试：1=SPI 通讯失败，2=加速度计 ID 不匹配，3=陀螺仪 ID 不匹配，4=加速度计配置失败，5=陀螺仪配置失败。读取通讯失败时报告错误并重新初始化，不打印上次缓存值冒充新数据。

若无输出，先确认 COM、TX/RX/GND、供电及串口参数；若乱码，检查波特率；若一直报初始化错误，检查 SPI 配置及板型。LED 的心跳仍监测默认任务，不代表 IMU 读数正常。

已同步 `robomaster-stage-one.ioc` 的 SPI1、USART1 和片选配置，并启用 HAL SPI/UART 驱动和 `-u _printf_float`，以支持 `snprintf` 的浮点输出。IMU 任务由 `freertos.c` 的 USER CODE 区创建，CubeMX 的任务列表中不用再重复添加。CubeMX 配置文件尚未在图形界面重新生成验证；重新生成后应检查差异，保留自定义任务和链接设置。

串口输出尚待硬件验证，已有编译记录见下节。传感器寄存器和时序参考工程已有的 `sp_middleware/io/bmi088` 驱动，以及 [Bosch BMI088 数据手册](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi088-ds001.pdf)；板级连线参考 RoboMaster C 型原理图与用户手册。
