# 第四步：单台位置控制实验

## 思路

目标角度与当前位置相减得到位置误差；误差乘位置增益得到期望速度，再与实测速度相减得到速度误差；乘速度增益得到电压控制协议值。

目标位置 → 缓慢变化的参考位置 → 位置误差 → 限幅目标速度 → 速度误差 → 限幅输出 → CAN。

使用两个比例环，无积分，不保证消除负载下的静态误差。现有增益只是未调试的初始候选值，不是已验证参数。

## 当前默认行为

control_constants.hpp 中 MOTOR_POSITION_ENABLE=false，所有档位输出零。串口 POSITION enabled=0，主动控制未开启。没有自动启用，也没有摇杆控制。

## 仅供到校后的启用实验

确认A=ID1、B=ID2、CAN1、电压模式0x1FF，反馈方向与电压指令正方向一致，两台角度有效。保持右下档，清空可恢复故障并准备；切中档后记录A当前位置，目标设为该位置+10°。参考以0.2rad/s渐变，目标速度限幅0.5rad/s，输出原始值限幅1500。B与同组其余位置一直填零。

这里的10°是逐步开发用的临时目标，与比赛最终中档IMU联动不同。左拨杆和摇杆都不参与；右上档停止，不实施箭头复位。离开中档后，再开始必须先下再中，新的目标从再次进入时的位置计算。

位置增益2.0（速度目标/角度误差），速度增益1000（协议原始值/角速度误差）。原始值1500不是1500V，也不是电流值。实际运动可能达不到目标、抖动或方向错误，不能凭编译通过判断可用。

## 停止与重新准备

遥控器离线/未解锁、任一电机离线或角度无效、CAN新错误/bus-off、任一温度达到60℃、A速度超过1rad/s、运行周期超过50ms、A相对进入位置偏移超过20°或计算非有限数时，控制器锁定故障、计算输出置零。健康条件恢复后需观察到右下档才能重新准备；累计角度失效仍需按第三步复位重新采集。

发送端若发现邮箱未空，撤销旧的待发帧并停止本次提交、锁定故障。下一轮才尝试发送零指令。out_raw是计算/请求值，不是电机收到或执行的证明。断线、CPU停机或硬件故障时，软件不能保证电机立刻无力。

目标速度限幅只是限制控制器的速度请求；实际超速检测在约20ms循环检查，不是可靠物理限速器。温度等门限也是本实验保守选值，不是厂家额定保护值。

## 串口显示

POSITION enabled：编译开关；active：位置控制计算是否运行；ready：是否已满足健康条件并观察到右下档；fault：是否故障锁定；target_rad：最终目标；ref_rad：逐步变化的参考；out_raw：计算输出。

## 模块

- motor_position.cpp/.hpp：两个比例环、渐变、状态和故障处理。
- motor_control.cpp：读取遥控器及电机快照、取得控制量、将A指令编码为两个大端字节。
- imu_task.cpp：显示POSITION状态。
- freertos.c与.ioc：默认任务栈改为512字（2048字节）；运行周期仍约20ms。

保留基础函数和结构体，没有类继承或积分控制。CAN接口头文件保持C可调用。

## 你需要参与

现在只有电脑，保持开关false即可。拿到硬件后，先完成前两步反馈检查、确认控制模式和方向、固定电机并留出移动空间、准备随时切断电机供电的手段；由导师协助确认后再改true、编译烧录、先下再中。方向错误或持续抖动立即停止实验再调参。

当前没有硬件结果，没有新增或运行测试用例。编译结果见README。此阶段不是完整比赛控制器：C板姿态、双电机比例联动、手动更新零点及复位仍待后续。
