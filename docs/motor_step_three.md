# 第三步：电机角度处理

## 目标

让 C 板知道电机相对本次开始观察的位置转了多少，而不仅仅知道单圈编码器值。当前仍然发送零电压，不启动任何主动位置控制。

## 为什么要做这一步

GM6020 单圈编码器是 0～8191。一圈有8192个计数，转过边界时会回绕。例如从8190到2，按最短方向实际增加4个计数，直接相减却是-8188。

处理流程：收到反馈 → 与上次位置相减 → 修正跨圈差值 → 累加计数 → 换算角度 → 串口显示。

- 差值大于4096，减8192。
- 差值小于-4096，加8192。
- 差值恰好为正负4096，方向存在歧义，标为无效。
- 单圈角度 = 当前编码器 × 2π / 8192。
- 相对角度 = 累计计数 × 2π / 8192。

例子：8190→2→10，累计计数依次为0、4、12。反过来2→8190，累计是-4。这是数学示例，不是实测结果。正方向目前以编码器数值增加为准，是否对应你观察到的逆时针，要到学校确认安装方向。

## 零点与失效处理

每台电机收到第一帧合法反馈时，把该位置作为本阶段相对零点。累计角度可以超过一圈，例如转两圈约12.566 rad；不自动回到零。

这不是最终箭头复位标定：两台电机分别在首次反馈时开始记录，尚未采集 C 板 yaw，也没有保存到掉电存储。

连续角度要求相邻有效采样间真实转动小于半圈。单圈传感器无法恢复通信中断期间到底转了几圈，不能用重新收到的数值猜测。

本阶段采用保守策略：反馈间隔达到10 ms（独立于100 ms在线门限）、恰好半圈歧义、CAN FIFO0溢出、bus-off或累计整数溢出，连续角度不再有效。重连后单圈值和ONLINE可以恢复，但已经锁定的连续角度保持无效，复位 C 板重新建立记录；不悄悄把当前位置设成新零点。

10 ms不是所有运动下保证正确的采样界限，只是当前保守策略。未被检测到的丢帧或高速运动仍可能违反半圈假设；反馈帧没有可供本程序使用的连续序号，valid=1不等于完整硬件验收。此处应结合实际反馈频率和速度进一步确认。

## 串口新增显示

```text
ANGLE A valid=1 single_rad=0.1000 relative_rad=6.2832 counts=8192
```

上面为示例。single_rad为传感器单圈角度，relative_rad是相对第一帧位置的累计角度，counts是累计整数计数。1圈=2π rad≈6.2832 rad=360°。

valid=0时不能拿累计角度去控制电机；累计值可能停留在最后可信位置。还应结合MOTOR行的ONLINE/OFFLINE判断单圈数据是否新鲜。短暂无反馈时打印快照先显示无效，后续恢复帧会确认时间间隔并锁定失效。

## 模块变化

- control_constants.hpp：一圈计数、半圈计数、角度连续性时间门限、2π。
- motor_control.h：累计计数、角度、有效标记。
- motor_control.cpp：update_motor_angle处理整数跨圈；motor_get_state复制快照后换算弧度。中断中不做浮点角度换算。
- imu_task.cpp：打印ANGLE行。

## 到学校后观察

先确认前一步CAN反馈正常。手动缓慢转动，观察跨0/8191时累计角度连续；转一圈相对角度应约变化6.2832 rad，反转应减少。复位后首次反馈将当前位置记作零。通信中断后应显示无效，重连不能冒充已恢复原连续位置；更换接线先断电。
