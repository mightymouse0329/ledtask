# 第二步：GM6020 通信与零指令阶段

## 本阶段范围

2026-10-05：接入 CAN1，读取两台 GM6020 的编码器、转速、电流反馈原始值和温度，周期发送零电压指令。

无论遥控器是否在线、拨杆在哪个档位，当前程序都只发送零指令。中档和上档仍然只是遥控器的模式请求，不会启动位置控制。本阶段没有姿态解算、PID、手动联动、参考零点调整或复位控制。**尚无实物验证，不能据此宣称已经完成“所有电机无力”的验收。**

## 配置假设（拿到硬件后确认）

| 项目 | 本次配置 |
| --- | --- |
| C 板总线 | CAN1，PD0=RX，PD1=TX，使用板上 CAN1 接口 |
| 比特率 | 1 Mbit/s；APB1=42 MHz，Prescaler=3，BS1=11，BS2=2，SJW=1 |
| A 电机 ID | 1，反馈标识符 0x205 |
| B 电机 ID | 2，反馈标识符 0x206 |
| 电机控制模式 | 电压控制；发送标准数据帧 0x1FF，8 字节全为零 |
| 发送周期 | 默认任务每轮调用一次，随后等待 20 ms，实际周期受调度影响 |
| 离线判定 | 从未收到有效反馈，或距离上次反馈达到 100 ms |
| CAN 中断 | FIFO0 接收及 SCE 错误中断，抢占优先级 5 |

位时序计算：42 MHz ÷ 3 ÷ (1 + 11 + 2) = 1 MHz。当前关闭自动重发，开启自动退出 bus-off，具体恢复效果待实物验证。

当前按 ID1、ID2 实现，修改 ID 时也要核对反馈过滤器和命令分组。0x1FF 同时覆盖 ID1～4，因此本阶段总线上只接这两台 GM6020，避免误影响其他设备。

### 零电压与失能的区别

用户提供的 GM6020 手册同时列出了电压和电流控制协议。ID1～4 的电压命令是 0x1FF，电流命令是 0x1FE；电流模式需要相应固件与调参设置支持。不要只改一个标识符就认定模式已配置正确。

本版本发送零电压。零电压不等于切断驱动，手动转动时是否有阻力、如何满足比赛“无力”要求，需要拿到硬件后确认控制模式和实测。若电机已开启电流环，本版本的电压指令可能被拒绝，手册描述可能出现橙灯常亮。应先确认实际模式，再推进下一阶段。

## 程序运行过程

1. `main()` 初始化 CAN1，再启动 FreeRTOS。
2. 默认任务先处理遥控器，再调用 `motor_service()`。
3. 首次调用启动 CAN、过滤器及接收中断；未成功时最多每秒重试一次。
4. 有空闲发送邮箱且没有 bus-off 时，提交一帧全零命令。无空位时记录跳过，不忙等。
5. 反馈到达后触发中断，检查帧类型、长度和编码器范围，解析并保存对应电机数据。一次中断最多处理三帧。
6. IMU 任务负责统一串口输出，每隔至少 500 ms 输出 CAN 摘要和 A、B 状态。IMU 初始化失败时打印会变慢，但 CAN 收发继续由默认任务和中断处理。
7. `motor_get_state()` 用很短的临界区读取完整快照，避免读到被中断更新一半的数据。串口发送在临界区外进行。

LED 心跳现在也覆盖默认任务中的遥控器服务和电机服务进度；它仍不是完整故障检测。

## 串口字段怎么看

继续使用现有 USART1 输出，串口助手设为 115200、8N1、无流控。以下是示例，不是实测：

```text
CAN started=1 bus_off=0 ZERO_ONLY queued=50 skipped=0 errors=0 flags=0x0 bad=0
MOTOR A ONLINE encoder=1234 speed_rpm=0 current_raw=0 temp_C=28 frames=1000
MOTOR B OFFLINE encoder=0 speed_rpm=0 current_raw=0 temp_C=0 frames=0
```

- `started`：本机 CAN 启动，不代表接线正确。
- `bus_off`：CAN 控制器当前是否因错误退出通信。
- `ZERO_ONLY`：固定只发零电压，任何拨杆位置均如此。
- `queued`：成功提交本机发送邮箱的次数，**不是收到 ACK 的证明，也不是电机成功执行次数**。
- `skipped`：bus-off、无空邮箱或提交失败导致的跳过次数。
- `errors` / `flags`：累计 CAN 错误事件与错误位；恢复后也可能保留，复位才清零。
- `bad`：软件发现的异常反馈帧数；硬件过滤器丢弃的其他 ID 不计入。
- `ONLINE`：最近 100 ms 内收到该电机有效反馈，不表示运动控制验收通过。
- `encoder`：单圈原始位置 0～8191，跨一圈会回绕；没有多圈累计，也没有箭头对齐后的零位。
- `speed_rpm`：转速，单位转/分钟。
- `current_raw`：电流反馈原始整数，未作安培换算。
- `temp_C`：摄氏温度。
- `frames`：该电机累计有效反馈帧数。

离线后保留最后一次数据供排查；从未收到反馈时为零。必须连同 ONLINE/OFFLINE 判断，不能把离线旧值当成实时测量。未接硬件时 OFFLINE 和 CAN 错误属于可预期状态。

## 到学校后需要你参与

1. 断电接线，向学长确认电源、CAN_H/CAN_L 线序及总线终端电阻。GM6020 额定供电为 24 V，CAN 信号线不能给电机供电。
2. A 设 ID1（第1～3位 ON/OFF/OFF），B 设 ID2（OFF/ON/OFF）。第4位是终端电阻开关，不是 ID；结合 C 板已有电阻确认总线两端终端配置，不要全部打开。
3. 确认电机电压/电流模式，先只接一台确认反馈，再接第二台；不要同时接 PWM 控制源。
4. 检查 ONLINE、frames 持续增加，手动转动时 encoder 变化；某台失去通信后应显示 OFFLINE。更换接线先断电。
5. 检查遥控器下/中/上档显示正常；当前始终 ZERO_ONLY，不会按联动比追踪位置。
6. 记录接线、模式、串口结果和异常，再进入运动控制调试。

“上电前手动对齐三个箭头”的约定留待复位阶段实现，本阶段未采集或保存零位。

## 文件与 CubeMX 维护

- `Core/Src/can.c` / `Core/Inc/can.h`：CAN 初始化、GPIO、NVIC。
- `applications/motor_control.cpp / motor_control.h`：零指令发送、反馈解析、状态快照。
- `applications/imu_task.cpp`：统一串口打印，避免多个任务同时占用 USART1。
- `Core/Src/freertos.c`：默认任务调用电机服务。
- `Core/Src/stm32f4xx_it.c`：CAN 中断入口。
- 已补入本机同版本 STM32Cube FW_F4 V1.28.3 的 HAL CAN 源文件和头文件，更新构建列表与 HAL 配置。

`.ioc` 已补充 CAN1、PD0/PD1、位时序和中断，但尚未经 CubeMX 图形界面重新生成核对。重新生成前保存当前版本，之后检查差异，尤其是 AutoRetransmission=DISABLE、AutoBusOff=ENABLE、IRQ 优先级5、CAN 源文件列表及默认任务服务调用。避免重复添加中断函数。
