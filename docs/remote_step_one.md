# 第一步：DT7 / DR16 基本通信

> 这是第一步的阶段记录。2026-10-05 已新增电机 CAN 反馈及零指令发送，当前行为请结合 [第二步指南](motor_step_two.md) 阅读；下文“未发送电机命令”仅描述第一步版本。

## 本阶段完成什么

接收 DT7 遥控器经 DR16 发出的 DBUS 数据，通过现有 USART1 串口打印在线状态、四个摇杆通道、左右拨杆、请求模式和 B 电机比例。

本阶段只解析控制意图，没有 CAN 初始化、GM6020 控制帧或电机输出，`DISABLED` 只是软件请求状态，尚不能作为电机物理失能的验收结果。

代码使用基础 C、普通函数和结构体。中断只接收、解析数据，串口文字由现有 IMU 任务发送，因此不会与另一个任务同时抢占 USART1。读取 IMU 失败时仍会输出 RC 状态，但间隔会随 IMU 重试延长到约 1 秒。

## 接线

1. 接线前断电，找到 C 板与 PWM 共用排针上的 DBUS 一列。
2. 按 C 板手册标记连接：A8=GND、B8=5V、C8=DBUS 信号。实际方位必须按手册 Pin 标记核对，不要只凭照片左右方向或线材颜色判断。
3. DR16 的 GND 接 A8、供电接 B8、DBUS 信号接 C8。
4. C 板已有反相电路，DBUS 经该电路进入 PC11 / USART3_RX；不要绕过反相电路直接接普通 UART 引脚。
5. 电脑输出仍使用外壳 UART2 四针口（芯片 USART1），接线与 IMU 串口任务相同，电脑设置仍为 115200、8N1、无流控。
6. 按遥控器手册完成 DT7 与 DR16 对频，确认双方指示灯状态正常。

接收机的 DBUS 与电脑的串口输出是两个不同接口：DBUS 使用 100000 波特率、8 个有效数据位、偶校验和 1 个停止位。STM32 HAL 中需配置 `UART_WORDLENGTH_9B` 加偶校验，才能获得 8 个有效数据位。

## 文件与执行流程

| 文件 | 作用 |
| --- | --- |
| `applications/remote_control.c` | 接收 18 字节数据帧、解码、检查范围和超时、产生模式请求 |
| `applications/remote_control.h` | `RemoteState` 数据结构、拨杆及模式常量、接口声明 |
| `Core/Src/usart.c` | USART3 配置，PC11 接收，中断优先级 5 |
| `Core/Src/stm32f4xx_it.c` | USART3 中断转交 HAL 处理 |
| `Core/Src/main.c` | 初始化 USART3 并启动接收 |
| `Core/Src/freertos.c` | 默认任务约每 20 ms 调用 `remote_service()`，处理超时和接收恢复 |
| `applications/imu_task.c` | 通过 `print_remote()` 输出 RC 状态 |

接收使用 `HAL_UARTEx_ReceiveToIdle_IT()`：36 字节缓冲区容纳数据，遇到串口空闲后只接受长度为 18 的完整帧。短帧、长帧、非法摇杆范围或拨杆值会使控制状态退回失能请求。

正常 DBUS 大约每 14 ms 一帧；仅接受连续三个合法帧后报告 `ONLINE`。四个摇杆原始范围 364～1684，减去中心值 1024 后显示约 -660～660。

## 拨杆含义

### 右拨杆

| 档位 | 原始值 | 显示请求 |
| --- | --- | --- |
| 下 | 2 | `DISABLED` |
| 中 | 3 | `LINK_REQUEST` |
| 上 | 1 | `RESET_REQUEST` |

上电或发生接收异常、失联后，需要先在通信正常时把右拨杆拨到下档，`ready` 才会变为 1。这样重新接通遥控器时，不会直接恢复此前的联动或复位请求。

`ready=1` 表示下档确认条件已满足，不代表电机已经上力。右拨杆仍在下档时，模式始终是 `DISABLED`。

### 左拨杆

| 档位 | B 电机预定比例 | 显示 |
| --- | --- | --- |
| 下 | 1:0.5 | `B_ratio=0.5` |
| 中 | 1:-1 | `B_ratio=-1` |
| 上 | 1:3 | `B_ratio=3` |

A 电机未来固定为 1:1。比例目前仅用于打印，不驱动电机。

## 串口观察步骤

完成编译、烧录后，打开现有串口助手。以下是示例，不是实际测量记录：

```text
RC ONLINE ready=1 R=DOWN L=DOWN mode=DISABLED B_ratio=0.5 CH=0,0,0,0 frames=120 errors=0
```

1. 遥控器未连接时应显示 `OFFLINE`、`ready=0`、`DISABLED`。离线时打印的摇杆和拨杆为程序设置的安全默认值，不是实际遥控器位置。
2. 接通遥控器，右拨杆置下，合法帧连续到达后显示 `ONLINE ready=1`，`frames` 持续增长。
3. 分别移动右水平、右垂直、左水平、左垂直摇杆，`CH` 的四个数字应分别变化；回中时通常接近 0。
4. 切换右拨杆，确认 `DOWN/MID/UP` 与实体拨杆方向一致，模式依次对应失能、联动请求、复位请求。
5. 切换左拨杆，确认比例依次为 0.5、-1、3。
6. 关闭遥控器，连续约 100 ms 没有合法帧后软件状态应回到离线、失能；打印时间还受打印周期影响。
7. 重新开启遥控器，保持右拨杆在中档或上档时应为 `ready=0`、`DISABLED`；先拨到下档，再切换才允许产生其他模式请求。

接收刚启动在一帧中间时，可能出现少量错误计数；如果 `errors` 持续增加，应检查接线、供电、对频和通信参数。DBUS 没有本程序可使用的 CRC，帧长与范围校验不能识别所有可能的误码。

## 验证状态与后续阶段

2026-10-04，本阶段完整 Debug 配置、编译和链接通过，编译输出未报告警告；Flash 使用 43868 字节，RAM 使用 19144 字节。尚无硬件运行结果，CubeMX 配置已同步但未通过图形界面重新生成检查。

后续按以下顺序推进：

1. GM6020 CAN 通信：确认使用 CAN1 还是 CAN2、两台电机不同的 ID、终端电阻与供电，读取编码器、速度及温度等反馈。
2. 实际失能：右下档、遥控器失联、电机反馈超时或控制异常时撤销电机输出，并清理控制器累计状态。以实际电机无力状态验收。
3. C 板姿态联动：添加 IMU 姿态解算与连续 yaw，建立 A 的 1:1、B 的三档比例，避免跨角度边界跳变。
4. 电机手动联动：识别外部转动，更新共同参考和 C 板参考零点，使另一台跟随，松手后不回原零位。普通刚性位置保持无法直接满足此项，需要单独设计并调参。
5. 复位：基于已标定的箭头方向和 C 板相对初始方向，将两台电机箭头对齐。已约定上电前手动对齐三个箭头，然后记录初始零位；目前用户没有硬件，电机 CAN 接口、ID 和安装方向仍待确认。

芯片接线参考 C 板手册 DBUS 章节；协议参考 DR16 用户手册及现有 `sp_middleware/io/dbus`。HAL 字长和校验位关系参考 [ST STM32F4 HAL 手册](https://www.st.com/resource/en/user_manual/um1725-description-of-stm32f4-hal-and-lowlayer-drivers-stmicroelectronics.pdf)。
